Giscus 很适合只想要一个评论框的静态博客：接入快，GitHub Discussions 也能直接保存讨论。但当评论后面还要连接签到、积分和用户主页时，继续把身份与内容留在第三方系统里就不太合适了。

这次把 Giscus 完整移除，换成由本站登录、由 Cloudflare D1 保存的自有评论区。第一阶段没有做充值，也没有接支付，只解决三个问题：谁能评论、评论存在哪里、怎样避免接口被随手刷爆。

## 先确定评论系统的边界

这次做的是可以直接上线的 MVP，而不是完整论坛：

- 所有人都能读取评论，不需要登录。
- 只有已登录用户能发表评论和回复。
- 作者可以删除自己的评论。
- 评论按文章保存，每页最多读取 20 条。
- 评论按纯文本显示，不走 HTML 渲染。
- 同一用户 15 秒内不能连续发言，10 分钟最多 8 条。
- 默认发布后立即可见，管理员审核队列留到后续阶段。

这样既保留了静态博客的轻量阅读体验，也让之后的签到、积分和用户中心有稳定的数据来源。

## 数据仍然放在 D1

新增的 `comment` 表保存文章标识、用户、正文、回复目标和状态：

```sql
CREATE TABLE comment (
  id text PRIMARY KEY NOT NULL,
  post_slug text NOT NULL,
  user_id text NOT NULL,
  body text NOT NULL,
  parent_id text,
  status text DEFAULT 'visible' NOT NULL,
  created_at integer NOT NULL,
  updated_at integer NOT NULL
);
```

另外建立了三个索引，分别用于文章时间线、用户频率检查和回复关系。

评论没有直接保存头像和昵称。读取时通过 `user_id` 关联 `user` 表，这样以后用户更新头像，历史评论也会自动显示新资料。公开接口只返回昵称和头像，不返回邮箱或 OAuth 凭证。

回复没有单独建表，而是保存 `parent_id`。评论列表会显示“回复 @某人”，删除时将状态改为 `deleted` 并清空正文，避免删除父评论时连带丢失其他人的讨论。

## API 分成读写两条线

读取评论走公开的 GET 接口：

```text
GET /api/comments?post=文章标识
```

它支持游标分页，并返回评论总数。即使没有登录，也能正常查看讨论。

发表评论走 POST：

```text
POST /api/comments
```

服务端先从请求 Cookie 中读取 Better Auth Session，再完成同源检查、正文长度检查、回复目标检查和频率检查，最后才写 D1。用户身份完全由服务端确认，前端传来的用户 ID 不会被信任。

删除自己的评论使用：

```text
DELETE /api/comments/:id
```

SQL 同时限定 `id`、`user_id` 和 `status = 'visible'`，因此不能通过修改请求参数删除其他人的评论。

## 为什么还要做同源和频率限制

登录能证明“是谁”，但不能阻止同一个人连续刷屏，也不能自动挡住跨站请求。

写入接口会检查请求的 Origin 是否与当前站点一致。正文会统一换行、移除空字符并限制在 1200 字以内。频率限制直接查询 D1 中该用户最近的评论，不需要额外的 KV 或 Redis。

这套限制对个人博客已经够用：

```text
最短间隔：15 秒
频次上限：10 分钟 8 条
正文上限：1200 字
```

评论正文始终通过 `textContent` 写入页面，而不是拼接 HTML。换行和中文会被正常保留，标签不会被当成页面结构执行。

## 静态页面怎么知道谁登录了

文章页仍然是静态 HTML，所以评论组件先渲染一个轻量外壳，再由浏览器并行完成两件事：

1. 调用 `/api/auth/get-session` 读取当前用户。
2. 请求当前文章的分页评论。

未登录时显示登录入口；登录后显示头像、昵称和评论输入框。点击消息里的“回复”会记录目标评论，提交时把 `parentId` 一并发送给服务端。删除完成后重新拉取第一页，评论数量也会同步更新。

从评论区进入登录页时，会把当前文章路径放进 `next` 参数。GitHub 授权完成后直接回到原文继续评论，不需要用户重新找页面。

## 部署时遇到的缓存问题

代码发布成功后，第一次检查正式文章页时，接口明明已经是新版，页面却仍然加载 Giscus。原因不是构建失败，而是文章 HTML 命中了旧的 CDN 缓存。

清理站点缓存后再次检查：

```text
文章页：200
自有评论区：已出现
Giscus：已消失
评论接口：200
未登录发表：401
响应缓存：no-store
```

这也是静态网站更新时容易忽略的一点：新部署成功、源站返回新文件、浏览器真正拿到新文件，是三件需要分别验证的事。

## 评论系统之后还要补什么

目前这版已经能支撑真实使用，但还不是最终形态。后续可以继续增加：

- 管理员置顶、隐藏和审核评论。
- 用户自己的评论历史。
- 评论举报与敏感内容处理。
- 评论奖励与防止重复领积分。
- 通知和回复提醒。

评论先跑通，再叠加签到与积分，比一开始就把论坛、支付和商城一起塞进来更稳妥。现在每一条评论都有真实用户、明确文章和独立记录，后面的积分流水也有了可靠的来源。
