图库最初只有一套本地工作流：把原图放进电脑上的素材目录，运行图片压缩脚本，再把生成的三档 WebP 上传到 R2。对站长来说这套流程可控，但不适合临时投稿，也不适合让访客参与。

这次把图库变成了两个入口：

- 站长专用上传：登录后直接发布。
- 公共投稿：任何人可以进入，但必须审核后才会显示。

公共投稿的每日额度也不同：

```text
未登录：每天 1 张
已登录：每天 5 张
```

它看起来只是一个上传按钮，实际需要同时处理图片压缩、对象存储、每日限额、身份判断、审核队列、缓存和删除恢复。

## 为什么选择浏览器压缩

R2 只负责保存对象，不会自动把一张原始照片变成多个网页尺寸。如果直接把几十 MB 的原图传到 Worker，再在服务端处理，请求体积和 CPU 都会成为负担。

因此图片会在浏览器里先生成三档 WebP：

```text
480w  用于列表缩略图
960w  用于常规显示
1920w 用于灯箱预览
```

浏览器只上传压缩后的结果，原图不会进入 R2。这样每次投稿通常只会产生数 MB 的上传，同时保留网页需要的响应式尺寸。

上传流程没有把 R2 密钥交给前端。浏览器只向 Pages Functions 提交三个 WebP，Worker 确认用户和配额后再写入 R2。

## 服务端不能只相信浏览器

前端已经限制了图片格式和大小，但服务端仍然需要重新检查：

- 确实收到 480、960、1920 三个文件。
- 每个文件的 MIME 是 `image/webp`。
- 文件头确实包含 WebP 标识。
- 单张和总大小没有超过限制。
- 标题、宽高和用户身份有效。

公开页面使用独立接口，普通用户无法通过修改请求参数获得站长直传权限。

## 匿名限额怎么实现

匿名用户没有账号 ID，所以使用 Cloudflare 提供的来源 IP 生成 HMAC 哈希。数据库只保存哈希，不保存原始 IP。

每天使用北京时间生成一个日期键，再对身份和日期执行原子计数：

```text
anon:图片哈希 + 2026-10-28 → 最多 1 次
user:用户ID   + 2026-10-28 → 最多 5 次
```

计数使用 D1 的唯一主键和条件更新，避免两个并发请求都读取到“0 次”后同时上传。

如果 R2 上传或投稿记录写入失败，系统会尝试删除已经上传的文件，并把当天计数退回。匿名用户第二次上传时，正式返回 `429`。

## 审核状态决定是否公开

每张在线图片有一条 D1 记录，状态分为：

```text
pending   待审核
approved  已发布
rejected  已拒绝
deleted   已删除
```

公共投稿默认进入 `pending`，图库公开接口只返回 `approved`。站长上传时直接写入 `approved`，并在审核信息里记录站长账号。

图库页面仍然是静态的，但加载后会自动请求已发布图片，与仓库内置图片合并。这样新投稿不需要重新构建网站就能出现。

## 删除也要区分来源

在线投稿和仓库内置图片不能使用同一种删除方式。

在线投稿的三个 WebP 都存在 R2，所以永久删除时会先停止公开，再删除三个对象。验证时删除后的图片链接直接返回 `404`。

内置图库和文章封面还承担文章封面引用。如果直接删除文件，文章封面可能一起失效。因此这类图片只记录一条“从图库隐藏”的状态：

- 图库页读取隐藏列表后移除对应卡片。
- 文章内部的封面仍然可以正常使用。
- 站长可以随时恢复显示。

这说明“从图库删除”和“删除源文件”不是同一个操作。

## 实际上线验证

这次分别跑了两条流程。

本地匿名投稿：

```text
第一次：201 Created，进入待审核
第二次：429 Too Many Requests
```

正式站长上传：

```text
三档 WebP 写入 R2
图片自动进入已发布列表
公开 API 能读取新图片
永久删除后 R2 三档文件均不可访问
隐藏内置图片后，隐藏列表出现记录
恢复后，隐藏列表清空
```

测试图片随后已经清理，没有留在公开图库。

## 当前边界

现在的上传进度是一个状态文字，没有做精确百分比。图片尺寸由浏览器提交，只用于图库布局；恶意尺寸不会造成服务端文件访问，但仍可能被审核前的脏数据干扰。

匿名额度按 IP 哈希判断，对普通误操作和低成本重复投稿足够，但不能替代更复杂的验证码、投诉和风控系统。

下一步可以继续增加：

- 投稿者查看自己的审核状态。
- 审核通过或拒绝后的通知。
- 批量上传和批量审核。
- 更完整的图片标签与搜索。
- 定时清理长期未通过的临时文件。

图库已经不再只是构建时读取的一组文件，而是静态资源、对象存储和数据库共同维护的内容系统。最重要的变化不是多了一个上传按钮，而是每一张在线图片都有了明确的来源、额度和审核状态。
