# 渔情B站直播助手机器人 · 使用手册

> 版本 1.0.4 · 更新于 2026-11-06  
> 公益项目，请勿挪用收费 · BUG 反馈群：1092065806  
> 项目地址：https://github.com/soramoe/yq-bot

渔情是一个跑在你自己电脑上的 B 站直播间助手。它连上你的直播间，记录弹幕、礼物、舰长和醒目留言，按你写好的规则答谢、欢迎、播报；数据、登录凭证和日志都留在本机，不经过第三方服务器。

它适合这样的主播：

- 想让欢迎、答谢、点歌、战报这些重复劳动自动完成；
- 想在下播后拿到一份能对得上账的战报，而不是凭印象；
- 想用 OBS 挂件把本场数据直接叠在直播画面上；
- 愿意花十分钟装一次，之后主要用网页操作。

它不做什么：不替你跟观众闲聊，不生成内容，不刷弹幕，不读别人的直播间弹幕，也不上传你的 Cookie。

## 1. 五分钟开始

1. 安装 **Node.js 22 或更新版本**（[nodejs.org](https://nodejs.org/)）。
2. 把整个文件夹放到一个固定位置，例如 `E:\渔情`。不要放在会同步的网盘目录里。
3. 双击 `scripts\install.bat`，看到 `[DONE] Environment is ready.` 即可。
4. 双击 `启动渔情.bat`，浏览器打开 `http://127.0.0.1:8900`。
5. 打开 `http://127.0.0.1:8900/login` 扫码登录 B 站，回到页面点右上角「⋯ → 换房间」，填自己的直播间号。

第一次启动默认是**演练模式**：事件照常记录，但不会真的发弹幕。先看一会儿，确认文案、冷却和房间号都对，再关掉演练。

## 2. 安装与启动

### 2.1 系统要求

- Windows 10 / 11（随包的 `.bat` 脚本按 Windows 写的）。
- Node.js 22 或更高版本。
- 一个能正常登录 B 站的网络环境。
- 不需要数据库，不需要 Docker，不需要额外安装依赖；安装包里已经带了唯一的依赖 `ws`。

### 2.2 安装

把压缩包解压到一个**固定、路径里尽量没有特殊符号**的目录。双击 `scripts\install.bat`，它会：

1. 检查 Node 版本；
2. 创建 `data\`、`logs\` 等运行目录；
3. 安装 `ws`（离线包已内置，没有网络也能装）。

安装只需要做一次。以后升级版本时，`data\` 不会被覆盖。

### 2.3 启动、停止与开机自启

根目录的 `启动渔情.bat` 是一个快捷入口，真正的逻辑在 `scripts\`：

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| 启动 | `scripts\start.bat` | 后台启动，已在运行会跳过 |
| 停止 | `scripts\stop.bat` | 按 PID 精确停止，并留下暂停标记 |
| 重启 | `scripts\restart.bat` | 改完服务端代码或换版本后用 |
| 查看状态 | `scripts\status.bat` | 版本、房间、账号、直播状态 |
| 开机自启 | `scripts\install-autostart.bat` | 登录自启 + 每 5 分钟巡检 |
| 取消自启 | `scripts\uninstall-autostart.bat` | 删除上面两个计划任务 |

两个容易误解的地方：

- **手动停止后，看门狗不会把你拉起来。** 停止会写一个暂停标记；下次手动启动会清掉它。
- **服务只看 8900 端口上的 `/api/status`，不看端口有没有被占。** 端口被别的程序占用时，脚本不会误报“已经在跑”。

日志在 `logs\service.out.log`，超过 5MB 自动轮转。

### 2.4 登录 B 站

服务启动后打开：

```
http://127.0.0.1:8900/login
```

用 B 站手机客户端扫码。扫码成功后：

- 凭证写入本机 `data\auth.json`，不会进 git，也不会出现在页面响应里；
- 服务会停掉旧连接，按原来的房间列表重新建连，**不需要重启进程**；
- 页面会收到一次重置，旧事件不会接在新连接后面。

要换账号，重新打开这个地址扫码即可；也可以在「维护 → 账号」里点「切换账号」。

### 2.5 填房间号

点右上角「⋯ → 换房间」，输入直播间号，真实房间号和短号都行，保存后就会连上。

- 最多同时盯 **10 间**直播间。
- 切换房间只是换视图，后台房间继续收弹幕、记日志；切回来数据还在。
- 插件文案和大部分设置是**全局**的，不按房间分开；场次统计、日志、战报、点歌队列按房间隔离。

### 2.6 演练模式

页面右上角有「演练模式」开关，默认打开。

- 打开时：连接、收事件、匹配插件、走完整个发送链路，但最后一步不真的发弹幕。
- 关闭后：真实发送。建议先用自己的小号或冷门时段试一次欢迎语和答谢语。

演练模式下页面上的「发送闸门」计数也会照常增长，可以判断规则有没有命中。

## 3. 界面速览

### 3.1 顶栏

顶栏分两行：

- 第一行：品牌、当前房间、连接状态、演练开关、主题切换、「⋯」更多菜单。
- 第二行：点歌队列、SC 待读、战报、PK 情报、付费用户榜。
- 「⋯」里是：插件、挂件、维护、换房间。

状态标签的含义：

| 标签 | 含义 |
| --- | --- |
| 真实发送 / 演练 | 当前是否真的会发弹幕 |
| B 站已连接 / 连接中 / 离线 | 弹幕长连接状态 |
| 服务告警 | 断线、直播中长时间安静、写日志失败 |

### 3.2 统计卡

统计卡横跨页面，显示本场五个数字：弹幕、进场人次、本场礼物、本场舰长、醒目留言。数字来自服务端投影，和战报同源。

### 3.3 实时事件

中间是事件流，可以按「全部 / 弹幕 / 礼物 / 进场 / 机器人 / 系统」筛选。机器人自己发出去的话会标成「发言」，并显示是否已发送、是否被截断。

页面只保留最近一段事件用于显示；完整历史在 `data\events\<房间号>\` 的日志里，战报和榜单都从日志重算。

### 3.4 右侧栏

常驻两张卡：

- **连接**：状态、人气、最近收包、事件数、重连次数；
- **账号**：登录状态、昵称、uid、校验凭证、退出登录。

访问口令、发送闸门、长期观众簿、插件、本场排行收在「更多状态与排行」里，点开才显示，避免右栏无限变长。

- **访问口令**：默认关闭。开启后同一台电脑的浏览器也要先输入口令，适合电脑不只你一个人用的情况。
- **发送闸门**：发送队列的计数——真实发送、演练通过、限速丢弃、重复丢弃、失败各多少，用来判断“为什么没说话”。
- **长期观众簿**：跨场次记录的到访观众，`#我来过` 和回访提醒都靠它。

### 3.5 窄屏与主题

- 服务只监听 `127.0.0.1`，默认不向局域网开放，所以手机不能直接打开电脑上的 8900。窄屏布局是为小窗口、分屏和以后可能的移动端入口准备的；真要在手机上远程看，需要自己做端口转发或反向代理，并注意访问口令和 Host 校验。
- 右上角太阳/月亮按钮切换浅色「海盐白」与深色主题，选择记在浏览器本地。
- 页面支持「添加到主屏幕」，断网时仍能打开界面外壳，但不会显示过期数字。

## 4. 几个先弄懂的概念

**房间 vs 场次。** 一个直播间可以有很多场。战报、统计卡、礼物目标都按“本场”算；下播再开就是新的一场。

**日志是事实。** 每一场的事件先写进 `data\events\`，统计、战报、榜单都从日志重放出来。所以重启、跨天、断线重连之后，数字仍然对得上。

**电池与元。** B 站礼物金额用“电池”，10 电池 = 1 元。页面和战报统一按这个口径显示；输入框写“元”的地方会自己换算。

**边沿。** 开播提醒、下播战报、OBS 切场景只在“状态真的变了”的那一下触发，重连补发的旧事件不会重复触发。

**插件总开关 vs 功能开关。** 插件页顶部的「启用」是整个插件参不参与；里面的「启用欢迎」「感谢关注」是具体功能。关总开关不会清掉你的文案。

**占位符。** 文案里的 `{用户}`、`{礼物}`、`{金额}` 会被替换成实时数据。写错或未知的占位符会原样保留，不会变成空白。

**`{用户}` 与可点 @ 二选一。** 模板里写了 `{用户}`，正文就会带上名字，系统不会再挂一个可点的 @；想要 B 站原生的可点 @，模板里就不要写 `{用户}`，让发送层自己挂。两者同时用会变成「@小明 感谢小明」，所以现在由发送层统一收敛成只出现一次。

## 5. 直播间设置

大部分设置集中在「⋯ → 换房间」的房间总览里，往下滚就能看到。

### 5.1 开播 / 下播提醒（webhook）

页内提示一直有；想推到群里的，在房间总览最下面填 webhook：

- 支持企业微信、钉钉、飞书机器人；
- 只认真正的开播 / 下播边沿：同一次开播不会重复推，重启补出来的“本来就在播”不会推，断线期间确实发生的开播/下播会补推一次；
- 勾上「下播后把本场战报发到同一个 webhook」，每次真实下播会先发提醒，再发本场战报；
- 平台返回 HTTP 200 但 `errcode` / `code` 非 0，也算失败；
- 发不出去只记一条警告，并在页面上补提示，不影响收弹幕和统计；
- 地址最长 500 字符，超长或格式坏会当场拒绝，不会悄悄截断。

日志里只保留 webhook 的域名，query 和路径里的密钥不会被写进去。

### 5.2 手机推送

和 webhook 是两套独立配置：群里和手机不是同一拨接收人。支持：

| 渠道 | 填什么 |
| --- | --- |
| Bark（iOS） | App 里的 key，或完整的 `https://api.day.app/<key>` |
| ntfy（全平台） | topic，或自建服务的完整地址 |
| Server酱（微信） | SendKey |
| Telegram | `bot_token|chat_id` |

- 开播、下播、大额消费会推手机；战报不推手机（太长，适合群里存档）。
- 渠道和目标必须成对，只填一半保存会报错。
- 配好后可以点「发测试」，真的推一条，成功或平台错误都会提示。
- 勾上「每周一 10:00 把最近 7 天的周报推到手机」，会按本地时区汇总当前房间最近 7 天的场次、时长、弹幕、进场、涨粉和收入；一场都没播也会发一句「没有开播记录」。

### 5.3 大额与回访提醒

在「付费用户榜」面板里设置：

- **单笔大额提醒**：满 ¥X 提醒。只看单笔礼物 / 一次上舰 / 一条 SC，不看累计；0 = 关闭。触发时页内 toast，配了 webhook 就同时发群。
- **回访提醒**：近 90 天累计满 ¥X 的老观众进房时提醒。只算本场开播之前的消费，本场刚送过的不算回访；同一场同一人只响一次；只发页内提示，不吵群。

金额单位都是元，保存时换算成电池。免费礼物金额为 0，不会触发。

### 5.4 本场礼物目标

房间总览里设一个本场目标（元，0 = 关闭）。达到 30% / 60% / 80% / 100% 时：

- 每一档只播一次，断线重连或日志重放不会又喊一遍；
- 一笔礼物同时跨几档，只播最高的那一档；
- 页内提示固定会响；「在弹幕里播报」是单独开关，关掉只是不在公屏说话；
- 四档都可以写自定义文案，支持 `{当前}`、`{目标}`、`{百分比}`，留空用默认；
- 目标按本场算，下播重开清零；中途改目标会按新值重新判断，已经播过的档位不会回退重播。

OBS 挂件会同步显示一条进度条；目标为 0 时整块隐藏。

### 5.5 OBS 场景联动

在房间总览里填 OBS WebSocket 地址、密码和两个场景名：

- 地址默认 `ws://127.0.0.1:4455`，OBS 28+ 自带 obs-websocket；
- 开播切到「直播中」，下播切回「闲聊」；
- 只在边沿连一次，切完就关，不常驻长连接；
- 密码只进不出，页面读回来只知道“设过没有”；留空表示不改，想清空有单独按钮；
- OBS 没开、密码错、场景名不存在都只记警告，不影响直播、统计和提醒。

### 5.6 服务健康告警

页面顶部状态灯默认不显示，出问题时变红；配了手机推送也会推到手机。会报三种情况：

1. 弹幕连接报错 / 关闭，或重连超过 5 分钟还没好；
2. 直播中 15 分钟没有收到任何事件；
3. 最近 10 分钟内写日志失败过。

同一类问题 30 分钟内只提醒一次；问题恢复后再坏会重新提醒。只对当前房间判断，后台房间断线不会在主播页上闪红灯。

## 6. 八个插件

点「⋯ → 插件」打开。顶部是插件标签，插件名旁边有总开关；下面的配置项**改完离开输入框就会保存**，不需要再点保存。保存失败会把界面退回旧值并提示。

每个插件底部还有「恢复默认配置」。

### 6.1 欢迎

观众进场、关注、分享、上舰时打招呼。

- **进场欢迎语**：默认「欢迎 {用户} 来到直播间」，可用 `{用户}`、`{粉丝牌}`、`{舰长}`。
- **上舰 / 续费**：上舰和续费分开文案。续费按报文里的标记区分；续费文案留空会回落到上舰文案。
- **关注 / 分享**：和进场共用同一张冷却表，先到的那条生效，不会连发两条。
- **同一人冷却**：默认 90 秒，0 = 不限。
- **同一人本场只欢迎一次**：默认开。只有 90 秒冷却挡不住“一晚进出十几次”。
- **老观众**：可选「说欢迎回来 / 和新观众一样 / 不打扰」。超过 30 天没来仍按新观众算，0 = 永远记得。
- **无粉丝牌时不显示 `{粉丝牌}`**：默认开，避免出现空括号。

建议：欢迎语里不要同时写 `{用户}` 和依赖结构化 @；想让名字可点，就删掉 `{用户}`。

### 6.2 礼物答谢

有人送礼物就道谢，连击合并成一句。

- **跳过免费礼物**：默认开。银瓜子礼物不花钱，全部答谢会盖住真正的心意。
- **只答谢不低于 X 电池**：默认 0，即不限。
- **连击合并**：默认开，合并窗口 8 秒；单个礼物先等 3 秒，最长等 20 秒。
- 单个和多个礼物各有一句文案，可用 `{用户}`、`{礼物}`、`{数量}`、`{电池}`。

连击的逻辑是“等一小会儿看还有没有下一个”，所以答谢会略有延迟；把「单个礼物先等」调小会更及时，但连击更容易被拆成好几条。

### 6.3 盲盒播报

有人开盲盒时播报开出了什么、赚了还是亏了。

- **只播报盈亏不低于**：默认 0 电池。低于这个值不单独播报，但仍会被当作普通礼物答谢，不会一条反馈都没有。
- **同一人冷却**：默认 30 秒；冷却期内的盲盒交回礼物答谢。
- 文案可用 `{用户}`、`{盒子}`、`{礼物}`、`{数量}`、`{成本}`、`{价值}`、`{盈亏}`、`{盈亏数}`。

盲盒默认优先级高于礼物答谢；它不播时，答谢插件会接手。

### 6.4 醒目留言答谢

SC 是花钱买了置顶的，每条都单独回：不合并、不冷却。

- **只答谢不低于 X 元**：默认 0。
- **复述留言内容**：默认关。弹幕上限只有 20 字，复述长留言会被截断。
- **留言最多保留**：默认 8 字，开启复述时才用。
- 文案可用 `{用户}`、`{金额}`、`{时长}`、`{留言}`。

SC 面板和「SC 待读」是两件事：插件负责答谢，待读面板负责让你不漏看。

### 6.5 关键词回击

弹幕里出现指定关键词时回一句，适合打卡、报时、固定问答。

- 规则一行一条，格式 `关键词=回复`；同一个回复配多个触发词用竖线：`你好|hi|hello=你好呀`。
- **匹配方式**：整句相等（默认，最安全）/ 以关键词开头 / 包含即可。热闹的房间里不要用「包含」，很容易刷屏。
- **同一规则冷却**：默认 60 秒。
- **忽略英文大小写**：默认开。
- 回复内容默认 `{回复}`，一般不用改；可用 `{回复}`、`{用户}`、`{关键词}`、`{内容}`。

### 6.6 定时播报

每隔一段时间自动说一句，用于暖场、轮播公告、提醒关注。

- **默认关闭**：它会周期性占用发送间隔，先写好文案再开。
- **每隔**：默认 600 秒，最低 60 秒。
- **只在直播中说**：默认开。
- **随机顺序**：开 = 每次随机；关 = 按顺序轮播，保证每句都说到。
- 文案一行一句，可用 `{时间}`、`{日期}`、`{房间}`、`{状态}`。

### 6.7 主动打招呼

不用人点，服务自己隔一段时间从最近来过的观众里挑一位，主动 @ 他说句话。

- **默认关闭**。
- **每隔**：默认 300 秒，最低 60 秒。
- **只挑最近来过的**：默认 600 秒内进过房间的人，避免 @ 一个早走了的观众。
- **刚进场先不 @**：默认 20 秒。刚进来时欢迎插件已经 @ 过，再 @ 会连着两条点同一个人。
- **同一个人冷却**：默认 1800 秒；0 表示只在轮完一遍后才重复。
- **挑人方式**：最久没被点过的（默认，雨露均沾）/ 最近进场的 / 随机。
- 招呼语文案可用 `{用户}`，也可以套用内置预设；预设不写名字，让 B 站 自己挂可点 @。

发送前会查一次高能榜：榜上命中才挂结构化 @；没命中或查失败就把名字写进正文、不传 @，宁可没有可点标签，也不在观众脸上留空位。查榜有 45 秒缓存，不会每个候选都打一次接口。

### 6.8 弹幕指令

观众发 `#帮助`、`#本场`、`#我来过` 时回一句。

- 只认“整条消息恰好是一个指令”，正常聊天里带井号不会被当成命令。
- 同一人冷却默认 15 秒。
- `#本场` 的回复可用 `{弹幕}`、`{进场}`、`{观众}`、`{礼物}`、`{舰长}`、`{SC}`。
- `#我来过` 会查观众簿，回答“上次是今天 / 昨天 / 3 天前来的”；第一次来用单独的文案。
- 三条回复都可以改，注意整句不要超过 20 字。

## 7. 点歌、SC 与付费用户

### 7.1 弹幕点歌

观众发一条以「点歌」开头的弹幕，例如：

```
点歌 晴天
```

就会进入点歌队列。

- 只认弹幕，SC 不参与；点歌是免费互动，没有金额这一列。
- 只收当前房间：后台房间的弹幕不会突然出现在页面队列里。
- 同一个人点同一首歌、且还在队里时，不会重复加，也不会重复播报。
- 队列最多 100 首，存在 `data\songs.json`，重启后还在；满了先丢已完成的，再丢最老的。
- 页面「点歌队列」上的数字是还在排队的条数，不含播放中那条。
- 面板里可以「播放 / 完成 / 跳过」：播放会把上一条放回排队，完成和跳过直接从队列移除；动作立即落盘，失败会整份回滚并提示。
- 进队会 @ 点歌的人播「已点歌：xxx」；点「播放」会播「接下来播放：xxx」。两句都走正常发言队列，说不了话不会卡住礼物 / SC 处理。

### 7.2 SC 待读

顶部「SC 待读」把日志里的醒目留言按时间列出来，默认最近 30 天，可切 7 天 / 全部，一次最多 500 条。

- 每条可以单独「已读」，也可以「全部已读」；状态存在 `data\sc-read.json`，换页面、重启都还在。
- 面板关着时来了新 SC，按钮上的红点会自己加一；打开后以服务端未读数为准，已读过的旧 SC 不会又变未读。
- 已读 id 只保留最近 5000 条，更早的会重新显示为未读，防止文件无限长。
- 换房间时红点清零，后台房间的未读不会挂到新房间头上。

### 7.3 付费用户榜

顶部「付费用户榜」按 uid 跨场次合并付费贡献：礼物、舰长、醒目留言三类分开记，免费礼物算个数但不计金额。

- 可切「最近 7 天 / 30 天 / 全部」，默认取前 30 人，最多 200 人。
- 榜上显示最近一次消费时间。
- 数字来自服务端重放日志，不是拿实时投影再算一遍，所以和战报对得上。
- 同一个面板里设置大额提醒和回访提醒（见 5.3）。

### 7.4 PK 情报

顶部「PK 情报」，填一个对面房间号（真实号或短号都行），保存后每 60 秒拉一次对面的公开信息：

- 只看公开数据：标题、直播状态、人气、粉丝数、高能榜前几；
- 不读对面弹幕，不猜比分，不往对面发任何东西；
- 第一次拉到的数据只用来建基线；之后只在对面「未开播 → 开播」「开播 → 未开播」的边沿提醒一次；
- 拉不到就保留上一次快照，超过 3 分钟标记「可能过期」，不拿旧数字当现状；
- 提醒走页内提示 + 手机推送（配了才发）；
- 房间号清空即关闭轮询，切房不会串到别的房间。

**开场自动播报。** 面板里可以开「开场 PK 时自动播报对面情报」。检测不靠弹幕，而是每 60 秒拉当前房间的 `getInfoByRoom`，`pk_id` 变了就是新一场，指定 PK、随机匹配、多人 PK 都支持。

播报分四段，中间停约 2.5 秒：

1. 迎战主播：`<名字>`
2. 在线人数：`<人数>`（取高能榜 `onlineNum`，不是直播间人气；拉不到就说“暂时看不到”，不编 0）
3. 前十贡献：`<合计>`（高能榜前十条的 `score` 相加）
4. 达到阈值说强，否则说一般

前三条整句都能改，但必须保留 `{名字}`、`{人数}`、`{贡献}` 占位符，删掉保存会拒绝。阈值默认 1000，0 = 永远算一般。同一场 `pk_id` 只播一次；四段播完之前，欢迎、关键词、定时问候这些插件发言会直接跳过，不排队，避免四段结束后一起涌出来。

## 8. 战报与复盘

点顶部「战报」打开「场后战报」。战报**只读日志**，不读内存统计，所以三个月前那场也能算出和当时一样的数。

### 8.1 场次卡片与每日趋势

- 汇总卡：场次、总时长、弹幕、进场、礼物、SC、大航海、总收入。
- 场次卡片：开始时间、时长、各项数字、峰值人气、备注、热门礼物。
- 每日趋势图：可以切弹幕 / 收入等指标；一天没播会补 0，不会把两根柱子挤在一起造成“连着播了 N 天”的错觉。

起点未知的场次显示 `≥`，结束时间是推算的显示 `约`，连接断了显示「本场已中断」——不把推断值装成精确值。

### 8.2 时间轴

每张场次卡片上有「时间轴」：把这一场按分钟切成格子，拖滑块回看。柱子是“这一格新增”，最后一格一定等于卡片上的总数。适合复盘“第 20 分钟弹幕为什么涨”。

### 8.3 高光时间轴

战报卡片上的「高光」会直接挑出值得回看的 12 个瞬间：

- 醒目留言 > 上舰 > 礼物，金额越高越靠前；免费礼物不计金额；
- 再补两处弹幕最密的时刻；
- 按时间升序排回去，每行是 `21:05:30（已播 12 分 34 秒）事件`；
- 「复制」拿一行，「复制全部」一次贴给剪辑；
- 没有值得回看的瞬间会明确写“没有”，不编。

### 8.4 战报海报

场次卡片上的「海报」生成 1080×1350 的 PNG，可以直接发动态、发群。

- 数字就用卡片上那一份，不重新统计；
- 热门礼物最多三条；
- 文件名是 ASCII 的 `report-YYYYMMDD-HHmm.png`；
- 浏览器不支持 canvas 会直接报错，不会给一张空白图。

### 8.5 月报 / 季报

战报面板右上角「月报 / 季报」，按自然月或自然季汇总，再和上一段做对比：

- 不是“最近 30 天”，是 11 月 1 日到 11 月 30 日这种边界，跨年也对；
- 看场次、时长、总收入、弹幕、进场、涨粉；
- 上期为 0 时显示「上期没有记录」，不编 +∞%；
- 「复制文本」拿到可直接发群的几行；
- 没有开播记录时直说，不生成全是 0 的假报表。

### 8.6 导出复盘页

战报 → 右上角「导出复盘页」，得到一份单文件 HTML：

```
yuyue3-report-7734200-2026-11-05_06-19.html
```

双击就能看，不需要服务在跑，也不需要联网。里面有汇总卡、两张柱状图、场次明细表，零脚本、零外链，可以当附件发出去，也能直接打印。数字和页面上的战报同源。

## 9. OBS 挂件

操作台是给自己看的，挂件是给观众看的。挂件地址：

```
http://127.0.0.1:8900/overlay.html
```

在 OBS 里加一个「浏览器源」，填这个地址，宽高按 1920×1080 建。页面本身透明且不挡鼠标（`pointer-events: none`），不会影响下面的画面。

不想手拼地址：点「⋯ → 挂件」，选主题、场景、要隐藏的卡片，面板会生成完整地址，点复制贴进 OBS。

挂件上有什么：

- 左上：房间标题、直播状态、已播时长；
- 左下：本场弹幕 / 观众 / 进场 / 礼物 / 醒目留言五个数字；
- 右上：付费用户 Top 5（60 秒刷新一次）；
- 右下：最近 5 条付费礼物 / 上舰 / SC；
- 数字上方：设了礼物目标时多一条进度条；
- 中间上方：大额提醒闪一条横幅，8 秒后消失；
- 没开播时显示「未开播」。

地址参数：

- `theme`：`default`（深色玻璃）/ `light`（浅色卡片）/ `warm`（暖色）/ `mono`（高对比黑白）；
- `scene`：`full`（全部）/ `compact`（只留标题和数字）/ `minimal`（只留标题和临时横幅）；
- `hide`：`paid`、`gifts`、`goal`、`stats`，用逗号分隔，单独关掉某一块。

例如：

```
http://127.0.0.1:8900/overlay.html?theme=light&scene=compact&hide=gifts,paid
```

参数写错会安静回落到默认，不会白屏。挂件只读：不登录、不写配置、不点已读；服务没开就只是连不上，不会拖垮主流程。

## 10. 更新

「⋯ → 维护」里可以检查新版本：

1. 点「检查更新」；
2. 有新版本点「下载更新包」；
3. 下载并校验完成后，才出现「重启并应用」；
4. 直播中会再确认一次，不会静默重启。

更新由独立进程执行：先备份代码，再替换，启动后做健康检查；起不来自动回滚。只替换代码条目，`data\` 一个字节都不动。

如果直连 GitHub 超时（常见 8 秒无响应），可以填更新镜像：

```
https://pub-1c052ae1726e4964913fac13a4cbd08f.r2.dev/yq
```

镜像只做转发，包仍然按清单里的 sha256 校验。也可以在 `scripts\proxy.txt` 写本机代理地址，重启服务后生效。

## 11. 授权

- 全新安装有 **7 天试用**，全功能。
- 试用结束进入只读：页面、日志、战报、榜单、挂件仍可看，所有发言暂停。
- 正式授权是 `data\license.json` 本地文件，Ed25519 验签，不联网、不上报。
- 授权绑 **机器码 + B 站 uid**。机器码由 MachineGuid 与 `data\install-id` 生成；换机器或删安装 id 都会变。维护 → 授权里可以直接复制机器码。
- 授权到期后有 7 天宽限，之后只读；`updatesUntil` 过期只挡“装新版本”，不影响直播。
- 把 `license.json` 放进 `data\`，刷新页面或重启即可。

个人版**预估参考价约 ¥199（含一年更新）**；最终价格与条款以购买页为准，程序里只显示“预估”。

## 12. 数据、备份与迁移

业务数据都在 `data\`，服务日志在 `logs\`：

| 路径 | 内容 |
| --- | --- |
| `data\events\<房间号>\*.jsonl` | 事件日志，战报和榜单的事实来源 |
| `data\app.json` | 房间、插件、提醒等配置（自动保留 `.bak`） |
| `data\auth.json` | B 站登录凭证 |
| `data\license.json` | 授权文件（如果有） |
| `data\songs.json` | 点歌队列 |
| `data\sc-read.json` | SC 已读状态 |
| `data\roster\` | 观众簿 |
| `data\backups\` | 更新时生成的代码备份 |
| `logs\service.out.log` | 服务日志，5MB 轮转 |

备份就备份整个 `data\` 目录。迁移时把整个程序文件夹复制到新机器，再装上 Node、跑一次 `install.bat` 即可；`data\` 里的日志和配置都会跟着走。

`data\` 不进 git，也不要放在 OneDrive / 坚果云这类同步目录里——日志在直播中会持续追加，同步客户端容易锁文件或产生冲突副本。

## 13. 常见问题

**页面打不开 / 启动失败。**  
先看 `logs\service.out.log` 末尾，确认 8900 没被别的程序占用；再跑 `scripts\status.bat` 看服务状态。

**检查更新 8 秒没响应。**  
本机到 GitHub 超时。配 `scripts\proxy.txt`，或在维护页填更新镜像。

**换账号后页面还是旧账号。**  
扫码成功后会自动重连；如果页面没刷新，手动刷新一次即可。

**机器人不说话。**  
按顺序排查：是不是还开着演练模式 → 对应插件的总开关 / 功能开关有没有开 → 是不是在冷却里 → 文案是不是超过 20 字被截断 → 发送闸门是不是在限速。

**欢迎语里没有可点的 @。**  
模板里写了 `{用户}`，正文已经带名字，系统不会再挂 @。想要可点 @，删掉模板里的 `{用户}`。

**webhook 群里没收到。**  
看页面有没有补「webhook 没发出去」；确认地址没超过 500 字符；企业微信 / 钉钉 / 飞书看返回的 `errcode` / `code`，HTTP 200 不代表成功。

**手机推送没收到。**  
先点「发测试」；Bark 检查 key，ntfy 检查 topic 是否订阅，Server酱检查 SendKey，Telegram 检查 `token|chat_id` 形状。

**授权显示只读。**  
试用到期、机器码变了、uid 变了，或签名不对。维护 → 授权里会写明原因；换机 / 换号按购买时的替换政策处理。

**挂件在 OBS 里是黑底 / 挡住鼠标。**  
确认地址是 `/overlay.html`，不是操作台首页；浏览器源宽高按 1920×1080；页面本身是透明且不接收鼠标事件的。

**OBS 没切场景。**  
确认 OBS 28+ 已开 WebSocket、地址和密码正确、两个场景名和 OBS 里完全一致；OBS 没开只会记警告，不影响直播。

**战报是空的。**  
战报按房间和日期读日志；确认当前房间号对、时间范围对，以及 `data\events\` 里确实有那几天的日志。

## 14. 边界与约定

- **不会自己找话题。** 只在事件触发或定时器到点时说话，不做开放式闲聊。
- **单条弹幕上限 20 字。** 文案太长会被 B 站截断；页面会标「已截断」。
- **有发送限速。** 同一时间大量事件时，发言会排队；说不了话不会卡住礼物 / SC 的处理。
- **插件配置全局共享。** 换房间不会换一套文案；场次、日志、榜单、点歌队列按房间隔离。
- **授权只在本机校验，不联网。** 请不要修改或删除授权 / 试用状态文件，否则会进入只读；换机、换号按购买时的替换政策处理。
- **不代替你登录。** 扫码用的是你自己的账号；凭证只在本机。
- **不读取别人的直播间弹幕。** PK 情报只看对面公开的房间信息和高能榜。
